# Compatibility Package 1.0.0

## Classification

Initial major release. There is no predecessor package and no data migration.

## Consumer Action

Consumers must select schema major 1, use the checked-in local schema registry,
and reject unknown majors with `COMPAT_UNSUPPORTED_MAJOR` plus this relative
migration path.

## Foundation Clarifications

The initial Cell foundation publishes discovery through the canonical SSM
parameter path, not an S3 access point. CONFIG candidates use
`jobs/<job_id>/config/<config_version>.json`. A Cell Contract checksum is the
lowercase SHA-256 of RFC 8785 bytes of the complete contract with `checksum`
omitted. These corrections clarify the initial release and do not introduce a
second compatibility major.

## Evidence Normalizer Clarifications

The initial package also defines the Scheduler-to-canonical-evidence boundary.
The Scheduler producer event ID is the SHA-256 of exact ASCII
`scheduler/v1` bytes containing the registered schedule ARN, scheduled time,
CONFIG version, and owner generation. Normalized envelopes may add the
secret-screened `payload_hash` and `trace_context` fields without changing the
1.x required envelope boundary. The normalizer has no ledger mutation; it emits
byte-identical canonical evidence for duplicate source delivery and delegates
deduplication to the later occurrence processor.

## Rollback

Before production adoption, revert the package and its tests. After adoption,
retain version 1 while any CONFIG, occurrence, queue, DLQ, investigation, or
rollback record references it.

## What worked well

1. Contract-first development created a consistent normative surface for schemas, enums, bindings, fixtures, checksums, and release registration.
2. Strict evidence binding and fail-closed evaluation protected the boundary between caller input, derived evidence, credential-free validation, and live AWS qualification.
3. Executable negative fixtures exposed wrong-target, stale-provenance, synthetic-evidence, approval, IAM/OIDC, retry, recovery, and malformed-artifact paths.
4. Independent adversarial, edge-case, and acceptance review found material issues that ordinary happy-path tests would not have exposed.
5. Runbooks and adoption documentation made ownership, alert handling, rollback, compensation, and operator boundaries explicit.
6. Repeated full validation gave a reproducible quality signal across Python, Terraform, security scanning, contract tests, and repository hygiene.

## Friction and growth areas

1. Provenance, caller-supplied result fields, and synthetic-evidence risks were repeatedly discovered late in implementation. The system needs earlier adversarial review at story-context and design boundaries.
2. Terraform provider deprecation warnings and dependency/DNS availability created validation friction. The warnings are documented, but the modernization work remains separate and visible.
3. Story and sprint tracking had inconsistencies, including story metadata that did not always agree with sprint status. Metadata validation should be part of completion, not a manual cleanup step.
4. The review evidence is strong but distributed across story files, review prompts, tests, runbooks, and validation logs. A standard evidence index should be produced with each completed epic.
5. The repository now has a complete launch and measurement framework, but it intentionally does not substitute for a named, approved, protected real-world pilot.

## Key lessons

- Treat provenance and authority as design inputs, not late validation details.
- Make every negative path executable and bind it to an authoritative source, not a caller-provided status.
- Keep credential-free validation, protected qualification, launch authorization, execution evidence, and final acceptance as separate state machines.
- Keep Terraform provider modernization isolated from feature work while preserving resource addresses and rollback paths.
- Make story metadata, review evidence, validation results, and sprint status one auditable completion package.

# Blocker-Only Final Adversarial Gate

## Verdict

**FAIL - the five prior blockers are closed, but two High multi-tenant authorization holes remain. No Critical findings remain.**

The current spine closes authenticated producer-class ingress, atomic terminal-alert outbox delivery, conditional job registration, the manual-occurrence identity domain, and the publish/validate/materialize/enable handshake. The remaining issues arise because authentication and uniqueness are not yet authorization: a job-owned Scheduler can still claim another registered job's coordinates, and an authenticated repository can still win a first-claim race for an application namespace it does not own.

## Closed Prior Blockers

- **Producer-class authenticity:** AD-5, AD-12, and AD-27 isolate producer queues, restrict principals/event types, and make the Cell normalizer stamp canonical identity.
- **Atomic alert delivery:** AD-14 commits a durable outbox in the terminal-state transaction and adds Stream dispatch, reconciliation, and notification-ledger deduplication.
- **Duplicate job identity:** AD-28 adds conditional Cell registration, immutable ownership generation, transfer controls, and policy derivation from the registration record.
- **Manual rerun identity:** AD-21 defines a separate `occurrence/manual/v1` byte domain generated by a trusted command handler.
- **CONFIG enablement race:** AD-29 defines machine states, acknowledgement evidence, a disabled first phase, and a policy-enforced reviewed enable phase.

## Remaining High Findings

### BLOCKER-01: Producer authentication is not bound to the registered job being asserted

**Severity:** High  
**Locations:** Diagram Scheduler/source queues (lines 30 and 36-44), AD-5 (lines 81-85), AD-12 (lines 138-142), AD-27 (lines 228-232), AD-28 (lines 234-238).

**Pair:** Job A's Terraform-owned EventBridge Scheduler and Scheduler execution role vs Cell normalizer/Process Manager for registered Job B.

**Compliant implementation A:** Each Scheduler delivery role can send only to the policy-isolated Scheduler source queue, and its message is limited to the allowed `LAUNCH` event type. Job A's module supplies a schema-valid body carrying `job_id`, `config_version`, generation, schedule time, and occurrence ID.

**Compliant implementation B:** The normalizer maps the Scheduler source queue ARN to the trusted Scheduler producer class, validates the body, stamps producer identity, and forwards it. The Process Manager verifies Job B's CONFIG and occurrence coordinates, then assumes Job B's launch role.

**Conflict:** AD-5 derives producer identity from source queue ARN, but neither AD-5 nor AD-27 requires the normalizer to bind asserted `job_id` and generation to the authenticated per-job Scheduler role or schedule resource. If Scheduler producers share a class queue, a compromised or misconfigured Job A schedule can emit a valid `LAUNCH` for Job B. All producer-class, schema, CONFIG, and occurrence checks pass, and the Cell launches Job B on Job A's cadence. This crosses the ownership boundary without assuming Job B's IAM role directly.

**Required closure:** Bind every job-scoped producer event to the Cell registration record. Either allocate a per-job source queue whose ARN maps to one ownership generation, or have the normalizer validate immutable SQS sender/schedule identity against `job_id`, schedule ARN, execution-role principal, generation, and registered owner before stamping. The Scheduler execution role and queue policy must be scoped to that binding. Add negative fixtures proving every Job A role/schedule is rejected when asserting Job B coordinates, config, generation, or occurrence.

### BLOCKER-02: Conditional registration permits authenticated namespace squatting

**Severity:** High  
**Locations:** AD-20 (lines 186-190), AD-27 (lines 228-232), AD-28 (lines 234-238), job-ID convention (lines 250-253).

**Pair:** Authenticated repository A with access to the reusable registration workflow vs the legitimate owner of application namespace `prod/payments/*`.

**Compliant implementation A:** Repository A submits the first registration for `prod/payments/reconcile`. The Registrar conditionally creates the binding to A's immutable repository ID, root identity, apply role, and caller-supplied owner metadata. A has not duplicated an existing ID and passes the current authentication rule.

**Compliant implementation B:** The legitimate Payments repository later submits the same syntactically valid job ID. AD-28 correctly rejects it as a duplicate/changed claim, and tombstoning does not automatically release the ID.

**Conflict:** Conditional first-writer-wins registration guarantees uniqueness but not entitlement. An application team can reserve another team's namespace accidentally or maliciously, block deployment before plan, and force a two-party transfer involving an illegitimate current holder. Binding caller-supplied `owner` after the claim does not prove that the repository is authorized for the `<environment>/<application>` prefix. This is a platform-wide denial-of-service and ownership-integrity gap.

**Required closure:** Add a Platform-owned namespace authorization registry mapping environment/application prefixes to approved immutable repository IDs, owning groups, and allowed apply-role principals. The Registrar must authorize the requested job ID against that registry before conditional creation; unallocated production namespaces require independent Platform/owner approval. Namespace administration must be separate from job registration, audited, and protected from self-approval. Add tests for cross-application claims, similarly named prefixes, repository transfer, deleted repositories, stale apply roles, and concurrent authorized/unauthorized claims.

## Gate Result

No Critical issues remain. Close BLOCKER-01 and BLOCKER-02 before treating account-local Cells as isolated multi-team platform boundaries or allowing parallel job onboarding.

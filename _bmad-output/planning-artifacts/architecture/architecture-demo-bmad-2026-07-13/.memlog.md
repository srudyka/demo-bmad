- (version) Research verified 2026-07-13 seed versions: Terraform CLI stable 1.15.8, AWS provider stable 6.54.0, and AWS Lambda Python 3.14 on Amazon Linux 2023; these are cold-start pins, not durable architecture invariants.
- (constraint) EventBridge Scheduler replaces <aws.scheduler.schedule-arn>, <aws.scheduler.scheduled-time>, <aws.scheduler.execution-id>, and <aws.scheduler.attempt-number> in target payloads; the occurrence contract may depend on scheduled-time but not execution-id, because retries receive distinct attempts.
- (constraint) SQS/Lambda and CloudWatch Logs subscription delivery are at least once, ECS task state events are durable, and all runtime handlers must tolerate duplicates and out-of-order signals.
- (constraint) Step Functions, enforced cancellation, public tasks, cross-account runtime orchestration, and a scheduler UI remain outside MVP.
- (assumption) Paradigm is an account-local cell-based architecture with an event-driven Process Manager; this isolates account/Region failures and gives one owner to occurrence state.
- (decision) Binds shared-vs-job ownership and prevents every job from creating incompatible runtime processors: Platform Engineering deploys one shared runtime cell per AWS Account and Region; application roots instantiate the per-job module and may reference but never own cell resources.
- (assumption) Binds missed-run detection and prevents uncorrelated time-window alarms: each job has paired EventBridge Scheduler schedules with identical expression/timezone and flexible windows disabled; one emits EXPECTED and one emits LAUNCH to the cell ingress queue using the same scheduled-time.
- (decision) Binds occurrence identity and prevents retries from becoming new runs: occurrence_id is the SHA-256 hex digest of schema_version, job_id, and canonical UTC scheduled_time; Scheduler execution-id and attempt-number are evidence, not identity.
- (decision) Binds event compatibility and prevents producers from inventing payloads: all cell inputs use a versioned JSON envelope with event_type, schema_version, job_id, config_version, scheduled_time, source_event_id, emitted_at, and payload.
- (decision) Binds launch configuration and prevents mutable or message-supplied authority: the per-job Terraform module writes an immutable CONFIG item keyed by job_id and a hash of launch-relevant configuration; runtime messages carry only job_id/config_version plus Scheduler context.
- (decision) Binds shared data ownership and prevents concurrent writers: only the Process Manager mutates OCCURRENCE and EVENT ledger items; Terraform owns CONFIG items; the deadline scanner and log ingestor are read/normalize producers and never write occurrence state.
- (decision) Binds occurrence lifecycle and prevents last-write-wins corruption: conditional DynamoDB transitions implement EXPECTED, STARTED, SUCCEEDED, FAILED, OVERDUE, MISSED, and AMBIGUOUS; repeated identical evidence is idempotent and conflicting terminal evidence becomes AMBIGUOUS.
- (decision) Binds ECS launch and prevents a shared broad RunTask role: the Process Manager assumes a job-specific launch role from the immutable CONFIG item, calls ECS RunTask, records task ARN or every failures entry, and passes occurrence_id/config_version into the container environment.
- (decision) Binds IAM separation and prevents privilege bleed: Scheduler delivery role can only send to cell ingress/DLQ; Process Manager base role can only read cell data and assume bounded job launch roles; each launch role can run one task-definition family on one cluster and pass only the exact ECS execution/task roles with iam:PassedToService=ecs-tasks.amazonaws.com.
- (decision) Binds completion truth and prevents a log line alone from declaring success: ECS task events and structured completion logs are correlated by occurrence_id/task ARN; SUCCEEDED requires one accepted success marker plus a zero essential-container exit, while nonzero exit or RunTask failure yields FAILED.
- (decision) Binds overdue detection and prevents independent timeout implementations: a minute-cadence deadline scanner queries the deadline-bucket GSI and emits DEADLINE_REACHED events to ingress; the Process Manager alone decides MISSED versus OVERDUE using launch/start evidence.
- (decision) Binds failure recovery and prevents message loss: ingress is an encrypted SQS standard queue with partial-batch Lambda responses, a 14-day redrive DLQ, and replay through the same versioned envelope; Scheduler target failures use a shared standard DLQ whose events retain scheduled time and schedule ARN.
- (decision) Binds multi-account behavior and prevents central runtime coupling: schedules, queues, processors, ledger, logs, metrics, alarms, roles, and task definitions remain in the workload AWS Account and Region; only code distribution and notification destinations may be centralized.
- (decision) Binds networking and prevents hidden NAT assumptions: platform Lambdas stay outside customer VPCs and call regional AWS APIs; ECS tasks run with assignPublicIp disabled in supplied private subnets/security groups and require caller-provided NAT or documented VPC endpoints.
- (decision) Binds metrics and prevents high-cardinality cost: custom metrics use bounded job_id, environment, and state dimensions, never occurrence_id; CloudWatch alarm state events go to an alert router that enriches notifications from the ledger with occurrence_id and Runbook context before publishing to the consumer SNS target.
- (assumption) Production retention defaults are 90 days for job/runtime logs and occurrence ledger items, 35-day DynamoDB PITR, and 14 days for ingress and dead-letter queues; non-production log retention defaults to 30 days, with longer values allowed.
- (decision) Binds Terraform composition and prevents cross-repository state coupling: a platform-cell module owns shared runtime resources, a job module owns job resources and CONFIG items, the cell publishes a versioned contract manifest through SSM Parameter Store, and consumers do not read another repository's Terraform state.
- (decision) Binds Terraform state and prevents environment overlap: each account/environment/root has an S3 backend key with bucket versioning, encryption, public access blocked, and native S3 use_lockfile=true; plan and apply roles are scoped to exact state and lock objects.
- (decision) Binds CI authority and prevents bypass of the approved workflow: production OIDC uses immutable repository IDs and a GitHub custom subject template that folds job_workflow_ref and environment into sub; AWS trusts exact aud/sub values and the reusable workflow is pinned by full commit SHA.
- (decision) Binds delivery and prevents applying an unreviewed plan: untrusted PRs run credential-free static checks; trusted PRs use a read-only plan role; production creates a fresh saved plan from the deployment commit, gates the apply job through a protected GitHub Environment, and applies that exact short-lived artifact with a distinct bounded apply role.
- (decision) Binds supply-chain reproducibility and prevents moving dependencies: Terraform, provider, module, workflow, and third-party Action versions are immutable; consumer roots commit provider lock files and production init uses -lockfile=readonly.
- (decision) Binds rollback and prevents destructive cleanup during recovery: disable paired schedules first, drain/replay queues, preserve prior CONFIG/task-definition/runtime package versions through the drain horizon, and restore the pinned cell/job version before deleting shared data.
- (constraint) ECS RunTask supports a caller-provided clientToken up to 64 characters and returns the original result for retries with identical parameters; the 64-character occurrence SHA-256 is therefore the launch idempotency token.
- (decision) Binds launch retry behavior and prevents crash-window duplicates: every RunTask call uses occurrence_id as clientToken and identical immutable CONFIG parameters; ConflictException or mismatched parameters transitions the occurrence to AMBIGUOUS and alerts.
- (decision) Binds schedule-pair consistency and prevents independent edits: expectation and launch schedules are generated from one Terraform local contract, carry the same schedule_generation hash, use separate schedule groups, and cannot expose independent expression/timezone/flexible-window inputs.
- (decision) Binds production schedule changes and prevents half-updated pairs: schedule expression or timezone changes use a documented two-apply maintenance flow—disable both, drain, update/verify both generations, then enable both—with explicit expected missed-window impact.
- (decision) Binds cell health and prevents two absent Scheduler signals from appearing healthy: a cell canary schedule emits every minute, the Process Manager emits a canary metric, and a missing-data CloudWatch alarm declares the regional cell unhealthy within five minutes.
- (assumption) A total EventBridge Scheduler outage that suppresses expectation, launch, and canary invocations is handled as a cell-wide incident; recovery uses Scheduler DLQ evidence and job schedule definitions to backfill affected occurrences as MISSED or AMBIGUOUS. Automated independent cron evaluation is deferred from MVP.
